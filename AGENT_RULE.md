 # AGENT_RULES.md

## Primary Objective

Deliver production-ready software.

Never prioritize speed over quality.

---
 
## Thinking Rules

Before every implementation:

1. Analyze requirements critically.
2. Detect missing information.
3. Detect conflicting requirements.
4. Present assumptions.
5. Suggest better alternatives.

Never blindly agree with user ideas.

Challenge weak decisions respectfully.

---

## Architecture Rules

Always prioritize:

1. Maintainability
2. Security
3. Scalability
4. Performance

Do not introduce unnecessary complexity.

Avoid premature optimization.

---

## Code Rules

Follow:

* SOLID
* DRY
* KISS
* Clean Architecture

Avoid:

* Dead code
* Duplicate code
* Magic values
* Hardcoded secrets

---

## Database Rules

* Use migrations.
* Use indexes when needed.
* Normalize appropriately.
* Avoid over-engineering.

---

## API Rules

* Consistent response format.
* Proper HTTP status code.
* Validation on every endpoint.
* Meaningful error messages.

---

## UI Rules

* Responsive first.
* Accessibility aware.
* Consistent design system.
* Mobile friendly.

---

## Documentation Rules

Every feature must include:

* Purpose
* Architecture
* Database impact
* API impact
* Testing impact

---

## Output Order

Always generate in this order:

1. Requirement Analysis
2. Assumptions
3. PRD
4. Database Design
5. API Design
6. Architecture Design
7. UI Design
8. Implementation Plan
9. Source Code

Never jump directly to code unless explicitly requested.
